# Threat boundaries

## Trusted inputs

- The checked-in schema and source code.
- A catalog snapshot generated by this repository from the configured Navigator instance.
- Explicit Figma component keys configured by the plugin user.

## Untrusted inputs

- User prompts and pasted/uploaded prototype JSON.
- Navigator and Bitbucket responses.
- Catalog snapshot files supplied through `XDCE_CATALOG_PATH`.
- Figma mapping JSON and remote component imports.

## Controls

- Navigator discovery is checked before invoking Bitbucket actions.
- Ingestion uses only read operations and fixed coordinates `XDCE0/xdce-widget@master`.
- Client payloads never contain `authMode`, `configFile`, credentials or cookies.
- API request bodies are capped at 1 MB and JSON shape failures are explicit.
- Prototype validation rejects invalid versions, dimensions, node kinds and duplicate IDs.
- Generation fails closed when the catalog is blocked and asks structured questions instead of selecting important options.
- Figma native instances are created only from explicit component-key mappings; otherwise the plugin creates a visibly labelled fallback.
- API responses disable caching and content-type sniffing. Production deployment must add platform authentication, authorization, TLS, rate limiting, audit logging and tenant isolation.

No proprietary assets or source snapshots are committed. The generated catalog should contain metadata and provenance only; review it before committing.
